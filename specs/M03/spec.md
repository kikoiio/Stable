# M03 权限、隔离与旧桥接受控接收 Spec

## 背景

M02 已让普通任务与长期目标工作项共用运行入口和流式事件，但工具请求目前只被记录，不会执行。Stable 现有权限检查针对旧目标能力；mewcode 的权限模式和规则允许更广的主机访问。旧 KiCad/电脑桥接仍有独立执行路径，其中修改动作可直接影响正式产物。

M00 要求 agent 在隔离候选区工作：正式产物只在用户审阅实际影响、经受信控制面接收后改变；长期目标的达标结论仍由独立复核产生。M03 先建立两类任务共用的权限与 Linux 隔离边界，再将旧桥接迁入该边界并走通候选审阅与接收。两个交付子项分别为 M03-A（通用权限与隔离）和 M03-B（旧桥接候选与接收）；M03-B 依赖 M03-A 的隔离验证。

## 目标

- 为普通任务、长期目标工作项和旧桥接建立同一套权限判定、授权交互与可追溯记录。
- 在 Linux 上验证文件、进程和网络的实际隔离；默认只允许读取授权项目数据，工具网络默认关闭，模型凭据留在受信服务侧。
- 隔离无法建立时拒绝文件写入、命令和其他依赖该隔离的操作，并说明原因。
- 让旧桥接的修改只产生隔离候选；用户审阅、接收后才改变正式产物，目标随后独立复核。
- 为 M04 等后续工具与扩展提供共同安全边界；通用工具循环仍由后续子项目接入。

## 功能需求

- **F1 共用判定**：普通任务和长期目标工作项使用同一权限规则。每次判断绑定本次运行的归属、授权目录、操作类型和资源边界；旧桥接也经过此边界。
- **F2 权限模式**：迁入默认、自动接受范围内编辑、计划和跳过重复提示模式。模式决定是否询问用户，不得越过明确拒绝规则、授权目录或操作系统隔离。计划模式的完整计划工作流留给 M06。
- **F3 文件边界**：默认只能读取授权项目数据；可写位置仅限隔离候选区。路径跳转、符号链接、子进程及旧桥接不能据此访问未授权数据或直接修改正式产物。
- **F4 执行与网络边界**：需要执行命令或修改文件时，先确认 Linux 隔离实际可用。工具网络默认关闭，只有用户明确授权的范围可开放；模型服务连接及凭据由受信服务管理，不交给工具环境。隔离失败时拒绝受影响操作，不静默降级。
- **F5 授权交互**：需要询问时向用户展示操作、目标、影响范围和原因；用户可拒绝、批准本次操作，或保存与该操作及范围精确匹配的规则。agent 不能代答或自行扩大授权；已保存规则也不能扩大硬隔离边界。
- **F6 可追溯结果**：允许、拒绝、等待用户、取消及隔离失败均产生可归属的结果。等待期间可取消；操作或授权范围变化后，旧批准不得复用。后续能力通过同一边界接入。
- **F7 旧桥接迁入**：旧 KiCad/电脑桥接的读写、命令及界面动作经过 M03 的权限与隔离边界。修改只作用于隔离候选；越界或隔离失败时，正式产物保持原样。
- **F8 候选审阅与接收**：受信控制面展示旧桥接候选的精确差异、适用检查、失败或不可用项、越界、授权事项和版本冲突。用户可取消、普通接收，或对已展示的限制明确强制接收；无法展示实际影响时不能接收。接收绑定候选、预览和正式版本，重试不重复应用；接收后目标须经独立复核才可能变为已验证。

## 非功能需求

- **N1 隔离不可绕过**：权限模式、已保存规则、工具参数、符号链接、子进程或用户后续强制接收均不能扩大本次运行的文件和网络边界。
- **N2 失败即拒绝**：隔离建立失败、规则损坏或授权信息缺失时，受影响操作不执行，用户能看到原因；不存在静默降级路径。
- **N3 决定可追溯**：每次授权决定关联具体运行、操作及当时的范围；重试和重连不重复执行，也不复用已失效的批准。
- **N4 凭据隔离**：模型密钥和宿主环境中的其他秘密不进入 agent 工具环境、权限提示、运行事件或错误输出。
- **N5 可验证性**：在 Linux 上使用真实隔离探测及越界、断网、取消等场景验证边界；自动化测试不依赖真实模型密钥或外网。
- **N6 旧桥接恢复正确**：候选、预览与接收在中断或重试后不会重复应用、丢失下一责任或错误地将长期目标标为已验证。

## 不做的事

- M03 不实现通用 agent 的文件工具、命令工具或模型工具循环；本阶段的候选接收闭环先由旧 KiCad/电脑桥接验证，M04 再接入通用工具。
- M03 不实现完整计划工作流、MCP、记忆、并行工作树或远程入口；这些后续能力须使用 M03 的边界。
- 首发不支持 macOS、Windows，也不提供绕过操作系统隔离或授权目录的运行模式。
- 本阶段不迁移旧会话和旧目标数据格式；桥接执行成功或用户接收均不能单独使目标变为已验证。

## 验收标准

- **AC1（F1）**：同一权限边界分别处理普通任务和目标工作项；跨运行、跨授权目录的请求被拒绝，决定保留正确归属。
- **AC2（F2）**：逐一验证迁入的权限模式及明确拒绝规则；选择跳过提示时仍不能越过授权目录、网络限制或操作系统隔离。
- **AC3（F3）**：尝试用相对路径、符号链接和子进程读取越界数据或修改正式产物，均不能越界；接收前正式产物内容不变。
- **AC4（F4）**：实际隔离探测成功时，授权操作在规定范围内运行；隔离失败时写入和命令被拒绝。工具默认无法联网，只有用户明确授权的范围可连通；工具环境读不到模型凭据。
- **AC5（F5）**：授权提示显示本次操作与影响范围；分别选择拒绝、单次批准、保存精确规则，验证后续相同操作与范围变化后的不同结果。
- **AC6（F6）**：权限决定及取消、失败结果可按运行和操作追溯；重连或重试后不会复用失效批准，也不会重复执行。
- **AC7（F7）**：旧 KiCad/电脑桥接在同一隔离边界内运行；修复只产生隔离候选，越界或隔离失败时不改变正式产物。
- **AC8（F8）**：用户看到候选的精确差异、检查结果和版本冲突后才能接收；覆盖失败项须明确强制确认。旧预览失效或重复提交不会再次应用；接收后目标仅在独立复核通过时标为已验证。
- **AC9（N1–N6）**：Linux 上完成真实隔离、断网、越界、凭据、取消和中断恢复测试；至少走通一次桥接修复的完整候选接收流程，以及一次强制接收后仍未验证的流程。
