## 需求与契约

- [x] **AC1 / F1：一套执行能力**。从 `unified-execution-v1.md` 的普通任务和目标工作项场景逐步追踪，二者均调用同一逻辑 `Run`，各有独立运行 ID 与归属；目标只在外层增加调度和复核。（验证：对照两条流程及 `WorkRef` 归属表，记录对应标题。）
- [x] **AC2 / F2：普通任务隔离候选**。普通任务场景包含生成候选、检查/预览、用户接收，接收前正式产物不变。（验证：按场景列出每一步的可写位置和正式版本。）
- [x] **AC2 / F2：目标工作项隔离候选**。目标场景遵守同样的候选与接收边界，agent 不能直接改正式产物。（验证：按场景列出每一步的可写位置和正式版本。）
- [x] **AC3 / F3：接收规则全覆盖**。规则表分别覆盖检查通过、失败、不可用、越界、授权问题、版本冲突，并对每行说明显示内容、普通接收或强制接收的选择与结果。（验证：逐行对照六类输入并记录表格位置。）
- [x] **AC3 / N3：强制接收只有用户可发起**。规则写明 agent 不得替用户确认，受信接收环节执行并记录被覆盖的限制，agent 沙箱权限不因此扩大。（验证：检查决定的发起者、执行者及隔离边界说明。）
- [x] **AC3 / N4：预览与实际影响一致**。预览包含实际差异、失败检查、越界路径和版本冲突；无法展示实际影响时不要求盲目确认。（验证：检查 `Review` 字段和异常规则；构造一项不可展示的影响，确认文档结论为不可确认。）
- [x] **AC3 / N2：旧确认会失效**。候选、展示内容或正式版本变化后需新预览与用户新确认；相同决定重试不重复应用。（验证：用三个变化案例及同一决定重试案例逐条核对规则。）
- [x] **AC4 / F4：正常目标验收**。目标场景包含独立复核通过和未通过两种结果，说明证据绑定接收产物与验收条件的版本。（验证：追踪 `Receipt` 至 `GoalAssessment`，记录状态和证据来源。）
- [x] **AC4 / F4：目标强制接收**。人工强制接收后正式产物可更新，但目标保持未验证并持久安排独立复核；凭据本身不使目标达标。（验证：逐步追踪强制接收场景的产物版本、目标状态及下一责任。）
- [x] **AC5 / F5：事实归属清晰**。归属表分别列出目标、条件、证据、待复核状态、agent 会话、工具输出及用户决定；工具输出与 agent 自述不能单独写成已验证。（验证：逐项比对归属表及一条目标场景。）
- [x] **AC6 / F6：共用 TUI 流程**。一个 TUI 入口能分别走通普通任务与长期目标的发起、进度、候选审阅和接收；目标还可见状态及证据入口。（验证：逐步阅读两条界面流程，记录各操作与可见结果。）
- [x] **AC6 / N2：重连视图可恢复**。界面流程说明按事件游标恢复运行事件，并读取持久候选、接收和目标事实，不靠会话最后一句判断结果。（验证：模拟 TUI 在候选产生后断开并重连，核对文档中的恢复步骤。）
- [x] **AC7 / F7：源端功能归属**。迁移地图将已识别的 mewcode CLI、TUI 与 `internal/` 功能归入 M01–M11，标出依赖、行为调整和可观察交付。（验证：对照源端入口与目录列表，记录未归属项目；预期无遗漏。）
- [x] **AC7 / N5：平台与切换边界**。迁移地图明确 Linux 首发、旧数据/命令不承诺兼容、后续可移除重建旧目标实现，而 M00 不删数据、不改运行代码。（验证：查找地图和契约对应段落，核对 `git diff` 无 Go 文件改动。）

## 端到端文档场景

- [x] **普通任务检查失败后强制接收**：用户在共用 TUI 发起任务 → 共享 agent 在隔离区产出候选 → 检查失败与差异可见 → 用户确认覆盖失败项 → 受信控制面接收并产出凭据。（验证：串读契约场景、接收规则和 TUI 流程；每个箭头都有对应文档步骤，接收前正式产物不变。）
- [x] **长期目标强制接收后复核**：调度目标工作项 → 同一 agent 产出候选 → 用户确认越界或版本冲突并强制接收 → 正式产物更新、目标仍未验证 → 独立复核被安排并使用新产物版本。（验证：串读契约场景、事实归属与状态规则；确认 agent 自述及接收凭据均不能直接写成达标。）
- [x] **预览失效与重连**：展示候选后正式产物版本变化 → 旧确认失效 → 重新预览 → TUI 中途断线重连 → 事件、候选和目标事实恢复。（验证：逐步核对版本绑定、重试幂等和事件游标规则；预期没有盲目应用旧确认或重复接收。）
