# Stable 统一 Agent 执行契约 v1

> 状态：M00 已批准的逻辑契约。面向后续逐项迁移；不固定 Go 签名、RPC、存储格式或具体 TUI 控件。首发平台为 Linux。

## 目的与原则

普通任务和长期目标工作项使用同一套 agent 执行能力。长期目标由 Stable 在执行能力外持续调度，并维护目标、验收条件、证据、状态和下一复核责任。两类任务共享一套终端界面。

agent 在隔离候选区中工作。受信控制面管理执行记录、检查、预览和正式接收。运行完成、候选接收、目标验证是不同状态；会话、工具输出与 agent 自述不能代替持久事实或独立证据。

## 词汇与状态

| 名称 | 含义 | 事实归属 |
| --- | --- | --- |
| 普通任务 | 用户发起的一次 agent 工作，不要求绑定长期目标 | Stable 的会话、运行与接收记录 |
| 目标工作项 | 由目标调度产生、服务于长期目标的一次 agent 工作 | Stable 目标、工作项、运行与证据记录 |
| 运行 | 一次有独立 ID、归属、基线和事件序列的执行 | Stable 持久记录；agent 会话是上下文 |
| 候选 | agent 在隔离区形成的文件变更和元信息 | Stable 持久候选记录及隔离工作区 |
| 检查 | 对候选执行的项目质量、授权范围、版本等检查 | Stable 检查记录；结果供用户决策 |
| 预览 | 将接收的精确差异、基线和全部检查发现展示给用户 | Stable 生成并绑定候选内容与正式版本 |
| 接收 | 用户决定经受信控制面应用候选并记录回执 | Stable 接收凭据及新正式产物版本 |
| 验证 | 独立检查确切正式产物是否满足目标验收条件 | Stable 目标评估和可追溯证据 |

状态依次可能为：待执行 → 执行中 → 候选待审 → 已接收/未接收。长期目标另有未验证、验证中、已验证、等待用户、等待外部变化等状态，并始终有下一责任或显式终态。某次运行成功不自动成为候选接收；接收成功也不自动成为目标已验证。

## 共用执行契约

| 逻辑记录 | 关键内容 | 约束 |
| --- | --- | --- |
| `WorkRef` | 普通/目标类型、会话 ID、可选目标与工作项 ID | 明确每次运行的归属；不要求共享会话。 |
| `ExecutionRequest` | 运行 ID、`WorkRef`、意图、正式产物基线、允许范围、资源与权限边界 | 普通任务与目标工作项均进入同一执行能力。 |
| `ExecutionEvent` | 运行 ID、单调序号、时间、类别、负载 | 记录文本、工具、状态和错误；供 TUI 实时显示及重连恢复。 |
| `Candidate` | 候选/运行 ID、基线版本、隔离区、变更清单、内容摘要 | agent 仅能修改隔离内容；接收前正式产物不变。 |
| `Finding` | 检查项、类别、通过/失败/不可用、说明、受影响路径或版本 | 记录项目质量、范围、授权、版本冲突及无法检查等发现。 |
| `Review` | 候选 ID、正式产物当前版本、完整差异预览、全部发现、预览摘要 | 预览须足以判断实际接收影响；不足以展示时不可确认。 |
| `AcceptanceDecision` | 候选/预览绑定、用户身份、普通/强制模式、明确覆盖项、时间 | 强制接收只能由用户明确确认，agent 不能代为决定。 |
| `Receipt` | 接收 ID、候选/决定 ID、应用后产物版本、时间 | 持久且幂等；表示产物已接收，不代表目标达标。 |
| `GoalAssessment` | 目标、产物/条件版本、独立证据、状态、下一复核责任 | 仅基于确切版本的独立复核可产生已验证结论。 |

逻辑操作：`Submit` 将普通任务或目标工作项转为独立执行请求；`Run` 在隔离区执行并发出事件、形成候选；`Review` 执行适用检查并生成预览；`Accept` 校验决定和预览绑定后接收候选；`Reassess` 对已接收的确切目标产物独立验收；`Read` 按会话/目标及事件游标读取统一视图。具体签名由对应子项目的 plan 定义。

## 检查与接收规则

检查结果用于告知用户，不会替用户做最终取舍。下表中“普通接收”表示在无未解决失败、不可用检查、越界、授权或版本冲突时按一般确认接收；存在这些发现时，用户可审阅后明确强制接收。

| 发现 | 预览必须显示 | 用户选择 | 接收行为 |
| --- | --- | --- | --- |
| 检查通过 | 检查项、结果、差异及基线版本 | 普通确认，或取消 | 按预览接收并记录凭据。 |
| 检查失败 | 失败项、输出摘要、关联差异 | 取消，或明确强制接收并确认覆盖失败项 | 受信控制面按已展示内容接收并审计覆盖项。 |
| 检查不可用 | 未执行检查、原因及未知影响 | 取消，或明确强制接收并确认检查缺口 | 记录检查缺口；不能宣称检查通过。 |
| 变更超出任务授权范围 | 越界路径、变更内容、授权边界 | 取消，或明确强制接收并确认具体越界项 | 用户决定可覆盖该检查限制；agent 权限不扩大。 |
| 操作需要额外授权 | 所需授权、对应操作和影响 | 取消，或明确强制接收并确认授权事项 | 受信控制面记录用户决定；agent 不自行获得新的工具权限。 |
| 正式版本已变化 | 候选基线、当前版本、需解决的差异 | 先基于当前版本重新生成预览，再取消或确认普通/强制接收 | 旧确认失效；新决定绑定新预览与当前版本。 |

用户确认前，界面必须展示实际将应用的差异、适用检查结果、失败或不可用项、越界路径、授权事项和版本冲突。若受信控制面无法计算或展示强制接收后的实际影响，该候选不能被确认或应用，须先重新生成可审阅候选。

接收决定绑定候选内容摘要、预览摘要和正式产物版本。任何一项变化都使旧确认失效。接收操作以唯一决定 ID 幂等：重试返回原有凭据或明确失败，不重复应用。受信接收层负责再次核对绑定并应用精确预览内容；agent 永远不能调用该权限。

## 普通任务流程

1. 用户从共用 TUI 提交任务。Stable 记录归属、意图、允许范围和正式产物基线。
2. 共享 agent 在隔离区执行；TUI 展示事件。运行结束形成候选，正式文件仍保持原样。
3. Stable 对候选运行适用检查，并生成差异与发现的完整预览。
4. 用户审阅后普通接收、明确强制接收或取消。检查失败、不可用、越界、授权或版本冲突均可由用户强制覆盖，但须确认对应发现。
5. 受信接收再次核对候选、预览、决定和当前正式版本，应用后写入接收凭据。若预览失效，要求重新预览与确认。

普通任务没有预设验收标准时，适用检查只提供决策信息；无论检查通过、失败或不可用，最终由用户基于差异与发现决定是否接收。

## 长期目标流程

1. Stable 根据目标事实、验收条件和下一责任持续生成目标工作项，并将工作项交给同一共享 agent 执行能力。
2. 每个运行保留目标/工作项关联、独立上下文和事件；agent 在隔离区形成候选。
3. 候选经过相同的检查、预览和用户接收规则。目标正常接收须有针对确切产物版本与条件版本的独立复核；接收后再核对正式版本，不能把运行日志或模型自述当证据。
4. 独立复核通过后，Stable 才能把目标标为已验证。复核未通过时目标维持未验证，并依目标策略继续派发工作或等待用户。
5. 用户强制接收后可更新正式产物，但目标保持未验证，接收审计标出被覆盖项，Stable 持久安排新的独立复核责任。只有后续复核才可能验证目标。

## 目标事实归属

| 事实 | 权威来源 | agent 内容的效力 |
| --- | --- | --- |
| 目标和当前状态 | Stable 目标记录与状态机 | agent 可提出建议，不能自行改变。 |
| 验收条件及版本 | Stable 持久目标条件 | agent 可读作上下文，不能替换条件。 |
| 工作项、运行及下一责任 | Stable 调度/运行记录 | agent 的计划或“还在处理”文本不能证明有后续责任。 |
| 候选与正式产物版本 | Stable 隔离候选及受信接收凭据 | agent 声称写入成功不能代替文件差异或接收回执。 |
| 检查与验收证据 | Stable 记录的工具/独立复核结果及来源版本 | 工具结果只证明其覆盖范围；agent 总结不能扩展证据覆盖。 |
| 人工接收与覆盖项 | Stable 用户决定及审计记录 | agent 不得模拟用户确认。 |
| 已验证结论 | Stable 对确切产物及验收条件版本的独立评估 | agent、执行事件或接收凭据单独均无此效力。 |

## 中断、重试与恢复

- Stable 持久化运行事件序号、候选、预览绑定、用户决定、接收凭据、目标状态和复核责任。会话上下文可丢失，权威事实不能因此丢失。
- TUI 重连后按事件游标继续显示事件，并读取候选、接收和目标事实；若运行尚未结束，明确显示执行/等待状态及下一责任。
- 若接收前发生中断，恢复后重新核对候选和正式版本；绑定不再有效就重新生成预览。不能自动重放旧接收决定。
- 若接收后、复核前发生中断，凭据仍表示已接收，目标仍未验证；恢复时继续或重新安排独立复核。
- 若目标条件或正式产物在复核期间变化，旧证据不验证新版本，目标回到待复核并产生新的责任。

## 共用 TUI 流程

**普通任务入口：** 用户进入会话并提交任务 → 查看流式 agent 事件 → 打开候选差异和检查发现 → 普通确认、强制确认或取消 → 查看接收凭据与正式版本。

**长期目标入口：** 用户从同一 TUI 查看目标及状态 → 查看当前/等待中的工作项和 agent 事件 → 审阅候选、差异和检查发现 → 普通接收、强制接收或取消 → 查看目标验证状态、证据来源、条件/产物版本与下一复核责任。

界面布局、快捷键和面板位置由 M01 决定。无论布局如何，两类任务使用相同的运行视图和候选审阅/接收语义；目标额外显示持久事实及证据。

## 迁移边界

- mewcode 的会话、模型流、工具、权限、沙箱、TUI、MCP、skills、hooks、memory、团队、工作树、CLI 和远程等已识别能力，按 [迁移地图](../../mewcode-migration-map.md) 逐项接入统一执行能力。
- 复用源码时适配本契约：agent 工具调用只能写隔离候选，授权与接收由 Stable 控制面执行，目标事实由 Stable 持久维护。
- 首发平台是 Linux。无旧命令或旧数据格式兼容承诺；后续切换可移除旧目标实现并重建。M00 本身不删除数据、不停服务、不修改运行代码。
- 每个后续子项目须独立完成 spec、plan、task 与 checklist 的审批后实现。
