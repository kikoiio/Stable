# M00 统一 Agent 执行契约 Plan

> 基于已批准的 [spec.md](spec.md)。M00 交付契约与迁移规划文档，不交付运行代码。下列记录与操作是跨子项目的逻辑边界；具体 Go 类型、函数签名、存储格式和 TUI 布局由实施它们的子项目确定。

## 架构概览

Stable 保留受信的长期服务作为控制面。一个共享的 agent 执行能力接收普通任务或长期目标工作项，在隔离工作区生成候选。控制面记录候选、运行适用检查、生成可供用户审阅的预览，并在接收时更新正式产物。长期目标在同一执行链外增加持久调度、事实存储和独立复核。一个 TUI 读取同一事件与事实视图，提供普通任务和长期目标的入口。

```text
普通任务 ───────┐
               ├→ 工作协调 → 共享 Agent 执行 → 隔离候选 → 检查/预览 → 受信接收 → 正式产物
长期目标工作项 ─┘                                                │
    ↑                                                           ↓
目标事实与调度 ←────────────── 独立复核 ←────────────── 接收凭据及产物版本

同一 TUI ← 运行事件、候选/预览、接收凭据、目标事实与证据
```

“共享”指同一执行实现及工具边界，不要求普通任务与目标工作项共用会话或进程。agent 只在隔离区写入；接收由受信控制面执行。运行完成、候选已接收、目标已验证是三个独立事实。

## 核心数据结构与接口契约

### 逻辑记录

| 记录 | 最低字段 | 约束及用途 |
| --- | --- | --- |
| `WorkRef` | `kind`（普通/目标）、会话 ID、可选目标 ID/工作项 ID | 区分执行归属；目标关联不改变共享执行器的实现。 |
| `ExecutionRequest` | 运行 ID、`WorkRef`、用户意图、正式产物基线版本、允许范围、资源/权限边界 | 由协调层提交；每次执行有独立上下文。 |
| `ExecutionEvent` | 运行 ID、单调序号、时间、事件类别、负载 | 将文本、工具、错误、状态等流式事件持久化；重连按序号恢复。 |
| `Candidate` | 候选 ID、运行 ID、基线版本、隔离区标识、变更清单、差异摘要 | 接收前只引用隔离产物；差异摘要与实际预览绑定。 |
| `Finding` | 项目 ID、类别、检查结果、说明、相关路径/版本 | 覆盖适用质量检查、不可用检查、越界、授权问题和版本冲突。 |
| `Review` | 候选 ID、正式产物当前版本、展示差异的摘要、全部 `Finding`、预览摘要 | 用户看到的内容必须足以识别将要应用的改动及被覆盖的限制。 |
| `AcceptanceDecision` | 决策 ID、候选 ID、预览摘要、决策人、普通/强制模式、已确认的限制、时间 | 强制模式只能由真实用户明确发起；agent 不能生成等价确认。 |
| `Receipt` | 接收 ID、候选/决策 ID、应用后的产物版本、时间 | 幂等接收的持久凭据；不等于目标验收通过。 |
| `GoalAssessment` | 目标 ID、产物版本、验收条件版本、独立证据、状态、下次复核责任 | 仅独立复核可使目标成为已验证；强制接收后保持未验证并安排复核。 |

摘要及版本标识的具体算法由后续子项目选择，但必须足以检测候选内容、预览内容或正式产物基线变化。不得把 agent 文本输出当作 `Receipt` 或 `GoalAssessment`。

### 逻辑操作

| 操作 | 输入 → 输出 | 保证 |
| --- | --- | --- |
| `Submit` | 用户任务或目标工作项 → `ExecutionRequest` | 分配独立运行 ID，记录归属和基线；普通任务与目标调用同一执行能力。 |
| `Run` | `ExecutionRequest`、事件写入端 → `Candidate` 或失败 | 只操作隔离区；逐条记录运行事件；结束本身不改变正式产物。 |
| `Review` | `Candidate`、当前正式版本 → `Review` | 运行适用检查并列出失败、不可用、越界、授权及版本冲突；生成与实际差异绑定的预览。无法展示实际影响时不提供可确认决策。 |
| `Accept` | `AcceptanceDecision`、对应 `Review` → `Receipt` 或需重新预览 | 校验用户身份、候选、预览摘要和正式版本；普通接收遵守通过的检查，强制接收记录被覆盖项；同一决策重试只产生一个接收结果。 |
| `Reassess` | 目标 ID、`Receipt`/产物版本 → `GoalAssessment` | 独立核验验收条件与证据；强制接收只触发未验证状态和复核安排，不能直接写入已验证。 |
| `Read` | 会话/目标 ID、事件游标 → 事件与事实投影 | TUI 重连后看到一致的运行、候选、接收、目标状态及证据入口。 |

这些操作是 M00 的协作契约，不锁定 RPC、Go 方法名或具体结构体形态。`Accept` 必须复核提交时看到的版本；候选或正式产物变化使旧确认失效，需重新生成并展示 `Review`。强制接收覆盖检查结论，不扩大 agent 的运行权限；仍须由受信控制面可准确展示并执行实际变更。

## 模块设计

### 工作协调

**职责：** 接收普通任务与目标工作项，生成 `ExecutionRequest`，区分运行归属与权限边界，调度同一 agent 执行能力。目标调度在此读取目标事实，普通任务无需目标记录。

**对外契约：** `Submit`，运行状态与事件游标。**依赖：** 目标事实（仅目标任务）、共享执行器和事件存储。

### 共享 Agent 执行器

**职责：** 管理模型对话与工具循环，按请求的权限边界在隔离区工作，记录事件，交付候选或失败。后续 mewcode 能力逐项接入此模块。

**对外契约：** `Run`。**依赖：** 隔离工作区、工具与模型适配层、事件写入端；不依赖目标验收实现。

### 候选检查与预览

**职责：** 比较候选和正式产物，执行适用检查，发现越界、授权及版本冲突，产出完整可审阅的 `Review`。检查失败或不可用不会自行推导目标已验证。

**对外契约：** `Review`。**依赖：** 候选、正式产物版本及检查器；不写正式产物。

### 受信接收

**职责：** 验证人工决定和预览绑定，按普通或强制模式应用候选，写入幂等 `Receipt` 与完整审计记录。只有此模块可将候选变为正式产物。

**对外契约：** `Accept`。**依赖：** `Review`、身份/授权上下文、正式产物存储。它不调用 agent，也不直接判定目标已验证。

### 目标事实与复核

**职责：** 持久保存目标、验收条件、证据、待复核任务和状态。消费接收凭据与产物版本，独立复核目标条件。强制接收后先写未验证与复核责任。

**对外契约：** `Reassess`，事实查询和目标工作项生成。**依赖：** 接收凭据、独立检查器和持久存储；不信任 agent 自述作为验收结论。

### TUI 投影

**职责：** 在同一界面发起普通任务、查看长期目标；显示流式运行、候选差异、检查与冲突、确认接收、目标状态与证据入口。操作通过控制面提交。

**对外契约：** `Read` 与用户命令。**依赖：** 控制面事件/事实视图、预览和接收接口；不直接修改正式产物或目标事实。

依赖方向为 TUI → 控制面；工作协调 → 执行器；执行器 → 候选/事件；检查预览 → 候选/正式版本；受信接收 → 预览/正式产物；目标事实 → 接收凭据/独立检查。目标调度读取目标事实后向工作协调提交新工作项，不形成执行器反向依赖目标事实的循环。

## 模块交互

### 普通任务

1. 用户在共用 TUI 提交任务；工作协调生成带普通任务归属、范围和基线版本的请求。
2. 共享执行器在隔离区运行，流式事件持久化，结束时形成候选；正式文件保持原样。
3. 检查预览运行适用项目检查，展示差异、失败/不可用结果、越界、授权及版本冲突。
4. 用户审阅后普通接收，或明确选择强制接收并确认被覆盖项。受信接收再次检查预览与版本，应用后写凭据；过期则回到第 3 步。

### 长期目标工作项

1. 目标事实与调度生成工作项；工作协调交给相同的执行器。每次运行保留目标/工作项关联和独立记录。
2. 执行器生成隔离候选；检查预览和受信接收遵守相同的候选机制。正常目标接收以独立复核和验收条件为依据；仅执行完成或 agent 声称成功不构成达标。
3. 正式产物接收后，目标事实基于确切的产物版本、验收条件版本与独立证据更新。未通过则继续未验证并按目标策略再派发工作。
4. 用户强制接收时，受信接收记录覆盖项并更新产物；目标立即保持或转为未验证，持久安排下一次独立复核。该复核后才可能得到已验证结论。

### 中断、重试和预览失效

- 决策绑定候选内容、展示差异和正式产物版本。任一发生变化，旧确认不能再次使用，须生成新预览并由用户重新确认。
- 重试同一接收决策返回既有凭据或明确的失败，不重复应用变更。接收成功与目标验收状态分别持久化，可在中断后恢复。
- TUI 重连以事件游标恢复流式记录，再读取候选、接收与目标事实；不能仅凭最后一条 agent 消息推断状态。

## 技术决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 运行入口 | 长期受信服务维护控制面；TUI 是同一服务的客户端 | 运行、确认、目标事实能跨界面重连和进程中断持续。 |
| 执行架构 | 普通任务与目标工作项使用同一 agent 执行实现；目标增加持久调度与独立复核 | 保持一条执行能力链，同时保留目标的长期事实。 |
| 文件修改 | 两类任务均先产生隔离候选，再检查、预览、接收 | mewcode 的直接工作区写入不能绕过 Stable 的候选边界。 |
| 人工强制接收 | 仅用户可在完整预览上明确确认；受信控制面应用并记录覆盖项 | 满足用户对检查失败、越界、授权和版本冲突的最终决定权，不给 agent 沙箱逃逸能力。 |
| 预览有效性 | 确认绑定候选摘要、展示差异和正式版本；变化后重新预览 | 确保用户确认的正是实际接收的内容。 |
| 长期目标结论 | 强制接收后保持未验证并安排独立复核 | 接收产物与目标达标有不同证据要求。 |
| TUI 数据源 | 读取持久事件及正式事实投影 | 流式显示与断线恢复、目标状态保持一致。 |
| 迁移方式 | 按功能逐项迁移，可复用源码则复用；允许旧目标实现移除重建 | mewcode 的 TUI 和 agent 模块耦合，逐项接入才能遵守统一契约。 |
| 首发平台 | Linux | 与已确认的平台范围及现有 Stable 环境一致。 |
