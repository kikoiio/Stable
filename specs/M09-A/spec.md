# M09-A 协作事件与只读协调原型 Spec

> 状态：已批准（2026-10-07）。M09-A 是 M09「并行协作与工作树」的首个子项目，依据 `mewcode-migration-map.md` 中「协作事件与只读协调原型」的先行范围。本轮采用父 run 批量委派、同步并行只读子 agent；后台任务、worktree 写入及 M07 fork skill/hook agent 入口留待后续 M09 子项。

## 背景

M00–M07-C 已建立共享 agent run、工具执行、会话事件恢复，以及技能和 hooks 扩展。M07 将 fork skill 与 hook agent 预留给 M09，M04 将 worktree 工具预留给 M09。当前尚无面向普通会话的并行子 agent 委派能力。

M09-A 先提供同步的只读协作入口：用户通过 `/delegate` 提交任务，由父 agent 拆分子任务并批量委派；多个子 agent 并行调查同一授权项目范围，结果回到父 agent 汇总。它不包含后台任务或工作树写入。

## 目标

- 用户能通过 `/delegate <任务>` 启动父 run；父 agent 可以把任务拆成多个明确子任务，并通过批量委派工具并行执行。
- 子 agent 只使用读、搜、列工具，不能写文件、运行命令或调用外部网络；模型请求仅使用父 run 已配置的 provider/model。
- 子 agent 只接收明确分配的任务和必要项目上下文；彼此隔离，不共享子任务结果；父 agent 收到每项结果和失败原因后汇总。
- TUI 能显示每项任务的排队、运行、阶段摘要和终态，不显示模型思考流；协作事件持久化并支持断线续读。
- 并发由有界资源池控制，批次可排队；取消父 run 会取消子任务。服务重启后，未完成子任务记为 `interrupted`，不自动重跑。

## 功能需求

- **F1 用户委派入口**：用户提交 `/delegate <任务>` 后，系统启动一个普通父 run；缺少任务时给出用法提示，不启动 run。父 agent 负责分析任务并决定是否拆分、何时调用委派工具。
- **F2 批量并行委派**：父 agent 可在一次委派工具调用中提交多个有明确目标的子任务。系统立即启动资源池允许的子任务，其余排队；队列全部完成或进入终态后，工具把逐项结果返回父 agent。批次同步等待，不转为后台任务。
- **F3 子 agent 边界**：每个子 agent 使用父 run 的 provider、model 和授权项目根，但工具集严格限于读、搜、列；不得调用委派工具、写文件、运行命令、使用 MCP/外部网络或扩展权限。模型 provider 通信属于必要请求。
- **F4 上下文与隔离**：子 agent 仅收到分配给自己的子任务和完成只读工作所需的项目上下文，不继承完整会话历史。子 agent 之间不共享上下文或中间结果；父 agent 可读取各子 agent 的最终结果。
- **F5 结果与失败**：每项结果单独标记成功、失败、取消或中断，并附可读摘要或失败原因。单项失败不丢弃其他成功结果；父 agent 收到全部终态结果后自行汇总。所有失败时也返回逐项错误，不能伪装为成功。
- **F6 协作事件与进度**：每项子任务产生排队、开始、运行进度和终态事件，并关联父 run、子任务和所属会话。TUI 展示任务名、状态、非思考流的阶段摘要和最终状态；不展示模型思考过程。
- **F7 持久化与恢复**：协作事件写入会话事件日志，断线后按游标恢复。服务重启时，尚未终结的运行任务和排队任务标记为 `interrupted`；同时将其父 run 终结为 `interrupted`，为未完成的委派工具调用补写明确的中断结果，保持工具调用/结果配对。恢复过程幂等，不自动重跑，也不把未完成任务显示为成功。
- **F8 取消**：父 run 被用户取消时，运行中子任务收到取消信号，排队项也进入明确终态；所有终态和可用结果返回父 run。
- **F9 资源约束**：同时运行的子任务数由有界资源池控制，等待中的任务排队；每项子 run 的时长、工具轮次和输出受独立上限约束，且不超过父 run 的授权与预算边界。

## 非功能需求

- **N1 权限安全**：子 agent 的能力只能收窄父 run 的权限，不能借委派越过授权项目根或现有工具边界。拒绝的能力不能通过提示词、参数或恢复流程重新开放。
- **N2 资源有界**：并发执行、每项时长、工具轮次和输出均有硬上限；大量排队任务不得创建同等数量的运行 goroutine，也不得无界占用内存。具体默认数值在 plan 中结合现有预算机制确定。
- **N3 记录隐私**：协作事件和最终结果遵循现有脱敏及大小限制；日志不包含模型思考流、provider 凭据或未过滤的敏感工具数据。
- **N4 事件一致性**：单个子任务的状态顺序明确，终态只能记录一次；断线重放、取消与服务重启后事件投影保持一致。
- **N5 兼容性**：普通 run、现有工具权限、候选接收与 M00 的目标事实边界不变；子 agent 只读结果不能直接成为目标验收证据。
- **N6 交付范围**：首版按迁移地图面向 Linux 本地会话。真实并行运行、会话持久化和 TUI 展示都要有可重复的本机测试证据。

## 不做的事

- 不实现后台子任务、任务完成通知或跨服务重启自动恢复；子任务只在父 run 的同步委派批次中运行。
- 不实现 worktree、分支管理、并发写入、候选区修改或正式工程接收；本轮子 agent 工具仅只读。
- 不启用 M07 预留的 fork skill 与 hook agent 入口；它们留给后续 M09 子项。
- 不实现长期存活的 agent、共享团队状态、子 agent 间通信、递归委派或跨会话/跨项目协作。
- 不开放 MCP、shell/命令、写工具或任意网络访问，也不新增第二套权限审批机制。
- 不把子 agent 输出自动作为目标证据、候选验收结论或目标状态变更依据。
- 不改变 M03/M04 的受控接收流程、M05 的会话恢复语义或既有 runner 的普通工具调用行为。

## 验收标准

- **AC1（F1）**：输入有效 `/delegate <任务>` 后能观察到普通父 run 启动；缺少任务时看到用法提示，且没有创建 run。
- **AC2（F2/N2）**：父 agent 在一次工具调用中提交多个子任务；超过资源池容量的任务排队，实测同时运行数始终不超过池容量，最终每项都进入终态。
- **AC3（F3/N1）**：子 agent 能读取、搜索和列出父 run 授权根内内容；写入、命令、MCP、递归委派及外部网络调用均被拒绝；越权路径访问失败。
- **AC4（F3/F4）**：记录 provider 调用和工具上下文，确认子 agent 使用父 run 的 provider/model 与权限根，只获得分配任务及必要项目上下文；不包含完整会话历史或兄弟任务结果。
- **AC5（F5）**：混合成功与失败的批次返回每项独立状态、结果摘要或失败原因；成功结果仍可汇总，所有失败时不会报告整批成功。
- **AC6（F6/N3）**：TUI 显示任务名、排队/运行/阶段摘要/终态，不显示思考流；日志经过现有脱敏和大小限制。
- **AC7（F6/F7/N4）**：断开后按事件游标重连，能恢复各子任务生命周期和当前状态；状态顺序合法且每个子任务只有一个终态。
- **AC8（F7）**：在运行和排队阶段重启服务，未完成子任务转为 `interrupted`；父 run 也写入 `interrupted` 终态，未完成的委派工具调用得到明确中断结果并保持调用/结果配对；重复恢复不会重跑、重复写终态或留下不可恢复的工具调用。
- **AC9（F8）**：取消父 run 后运行中子任务停止、排队任务取消，父工具调用返回清楚的终态，不遗留活跃子 run。
- **AC10（F9/N2）**：单项子任务达到时长、工具轮次或输出上限时停止并报告原因；高负载批次下并发和内存使用保持有界。
- **AC11（N5/N6）**：现有普通 run、权限门、候选接收和目标验证回归通过；只读协作结果不会改变候选、正式工程或目标验证状态。
- **AC12（N6）**：Linux 本机测试覆盖真实 runner 并行、取消、重启恢复与 TUI 投影；需要模型服务的行为通过 fake provider 验证，不依赖真实费用或网络。
