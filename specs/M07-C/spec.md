# M07-C MCP Spec

> 状态:已批准(2026-10-06)。依据迁移地图 M07 行及三子项拆分决定(M07-A skills+命令关联 → M07-B hooks → M07-C MCP);用户已确认:MCP prompts 不做(源端未实现,与源端对齐)、配置采用「用户级主配置 mcp_servers 键 + 项目级 .stable/mcp.yaml」两级合并(同名项目覆盖用户)、热更新为 mtime 自动 + /mcp reload 手动、hooks http 动作在本项一并实现、协议实现采用官方 Go SDK、MCP Manager 由 conversation 服务单一持有、stdio/Streamable HTTP/SSE 三传输全迁、加载策略为 eager+dispatch(M07-A 已定,丢弃 native/defer_loading)。

## 背景

Stable 经 M00–M07-B 已具备统一 agent 执行(runner、工具执行、权限审批)、持久会话与压缩、统一命令注册表(M06)、技能(M07-A)与 hooks(M07-B)。MCP(Model Context Protocol)是外部工具服务器的标准接入协议:用户声明 MCP 服务器(本地子进程或远程 HTTP 端点),agent 发现其工具并像内置工具一样调用。

mewcode 源端 `internal/mcp`(基于官方 Go SDK,约 700 行)提供行为参照:主配置 `mcp_servers` 键七字段、启动时 eager 连接全部服务器、stdio 探测 10 秒超时回退旧握手、工具以 `mcp__<server>__<tool>` 命名进统一注册表、eager/native/dispatch 三档加载、prompts/resources 未实现、无热更新、`/mcp` 只显状态。此前已确认的边界:M07-A 定下 Stable 加载策略为 eager+dispatch(丢弃 native/defer_loading);M07-B 把 hooks 的 http 动作留到本项一起实现。

Stable 与源端的架构差异:Stable 是客户端-服务端架构(TUI 经 Unix socket 请求会话服务),因此 MCP Manager 由 conversation 服务单一持有;源端四入口各自建 Manager 的模式不迁移。

## 目标

- 用户声明 MCP 服务器后,agent 能发现并调用其工具,调用走 M03 权限门与 M04 工具协议,不绕过既有边界。
- 连接、调用、失败三条反馈链完整可观察(用户与模型各自看到该看的)。
- 配置支持热更新(mtime 自动 + /mcp reload 手动),变更可审计。
- hooks 的 http 动作在本项一并实现,M07 三个子项全部收口。

## 功能需求

- **F1 配置发现与解析**:用户级主配置 `config.json` 新增 `mcp_servers` 键(数组),项目级独立文件 `<项目根>/.stable/mcp.yaml`,两级合并生效:同名条目项目覆盖用户(保留项目条目位置),用户条目在前。每条字段:`name`(必填,非空)、`command`+`args`(本地 stdio 服务器)、`url`(远程端点)、`transport`(仅 `url` 时有效,`sse` 走 SSE、其余走 Streamable HTTP)、`headers`、`env`(均为 map);`command` 与 `url` 恰有其一,两者都空或都非空为非法。加载校验:文件大小与条目数有上限,超限条目/文件跳过并进加载报告;非法条目整条跳过,不阻塞其他条目与服务。`env` 与 `headers` 的值不落日志、在使用时经环境变量展开(展开在服务进程环境上,不进沙箱)。

- **F2 连接生命周期**:agent 就绪后自动连接全部服务器(eager,无 lazy):`command` 非空以子进程 stdio 连接(stderr 丢弃,防转义污染输出);`url` 非空按 transport 连接。stdio 先发新版协议探测,10 秒无响应回退旧版 initialize 握手(对用户不可见)。连接失败或工具列举失败:记明确错误并跳过该服务器,本会话不重试、不自动重连;其余服务器不受影响。服务关闭时有序断开全部连接并终止子进程。连接完成后一次性决定工具加载模式并整场固定(保证提示缓存前缀稳定)。

- **F3 工具暴露**:连接成功后列举工具,以 `mcp__<server>__<tool>` 命名注册进统一工具注册表(server/tool 名中非字母数字字符归一为 `_`);同名工具后注册覆盖先注册。按 schema 估算体积分两档:小于阈值(上下文窗口的 10%,估算法与源端一致)的为 eager,直接进模型工具清单;超限的为 dispatch,不进清单,模型经发现工具按名查询 schema、经 `mcp_call` 工具调用(参数按目标工具 schema 强转后透传,调用用服务器原始工具名)。环境变量可强制指定加载档位。`mcp_call` 与发现工具必须在 MCP 连接建立前注册(缓存前缀不变式)。

- **F4 工具调用**:MCP 工具(eager 直调与 `mcp_call` 分发同路)走统一工具执行路径的 host 分支:pre_tool_use hook 先行 → 构造权限操作过 M03 权限门(默认 ask,可按 server/tool 配置 allow/deny/ask 规则,deny > ask > allow)→ 调用服务器。结果只取文本内容(多条以换行连接,空结果给 `"(no output)"`,图片等非文本内容不透传);服务器业务错误以错误标记透传给模型;传输层失败包装为明确的调用失败错误;`mcp_call` 找不到目标工具时报错并列出全部可用工具。

- **F5 失败反馈**:三种形态分别可观察——① 连接失败:`MCP server '<名>': <原因>` 进加载报告与状态栏,该服务器工具对模型不可见;② 调用失败:模型收到带错误标记的失败消息;③ 未知工具:模型收到含可用工具清单的指引错误。

- **F6 服务器指引注入**:服务器握手返回的 instructions 非空时,首轮 run 以系统提醒注入「MCP Server Instructions」(与技能 delta 提醒同位置),每会话一次、不重复。

- **F7 热更新与 /mcp**:用户级主配置与项目级 `mcp.yaml` 的 mtime 变化后自动重载(仅应用 `mcp_servers` 键,主配置其余键一律不热生效);`/mcp reload` 手动触发。重载语义:断开受影响服务器的连接并终止其子进程,按新配置重建;新增/删除/变更的服务器集合差异可观察;`/mcp` 无参列出各服务器(名称、来源层级、连接状态、工具数)与加载报告;每次重载落会话事件,重启后投影一致。

- **F8 hooks http 动作**:替换 M07-B 的「未启用」桩——向 hook 配置的 URL 发起真实 HTTP 请求(URL/Method/Headers/Body 字段沿用已保留的解析;headers 值同样使用时展开)。用户显式写入配置即受信,与 command 动作同信任级,不经权限门;响应体(截断至上限)作为 hook 输出按既有回流语义注入下一轮 run;请求超时可配(默认对齐 command 动作量级),超时与一般失败可区分,`on_error` 语义适用。

- **F9 审计**:MCP 工具调用复用既有工具调用/结果事件对(含输入脱敏);服务器连接、断开、重载落新的会话事件族(含成功与否与原因摘要),重启后会话投影一致。

## 非功能需求

- **N1 上限与超限**:配置文件大小、服务器条目数、单服务器工具数、hook http 响应与 MCP 输出长度均有上限;超限截断或跳过并在报告中可见,不崩溃、不阻塞输入(数值在 plan 定,量级对齐 M06/M07 既有惯例)。
- **N2 安全**:`env`/`headers` 值与展开结果不落会话日志;工具调用输入经既有脱敏管道后再落盘;MCP 工具默认 ask,权限边界由 M03 单点掌握,本项不引入第二套判断;stdio 服务器进程在服务进程环境下启动(非沙箱),其权限与 command hook 同级(用户显式配置即受信),此边界明确写入文档。
- **N3 性能与缓存**:schema 体量按字符估算 token(系数与源端一致);工具清单按名排序;加载模式连接后一次固定、运行期不变,保证提示缓存前缀稳定;连接在后台进行,不阻塞 TUI 输入。
- **N4 协议兼容**:新版协议探测失败自动回退旧版握手;SSE 仅为老服务器保留并在配置说明中标注弃用。
- **N5 稳定性**:非法配置、不可读文件、符号链接、服务器进程立即退出等异常一律跳过/截断 + 报告;TUI 与会话服务不崩溃;会话重启后事件投影一致。

## 不做的事

- 不做 MCP prompts / resources / logging / completion(源端未实现,与源端对齐;prompts 暴露为命令留待真实需要时另立小项)。
- 不做 native/defer_loading 模式(Anthropic 端点私有 beta,M07-A 已定丢弃,Stable 只有 eager+dispatch 两档)。
- 不做自动重连、健康检查、服务器进程守护(对齐源端:失败即本会话跳过)。
- 不做 MCP 服务器的 OAuth/认证流管理(headers + env 展开已覆盖现有需要)。
- 不做图片等非文本内容透传(仅文本,对齐源端)。
- 不做主配置其余键的热生效(仅 `mcp_servers`)。
- 不改 M03 权限门与 M04 工具协议的任何既有语义——MCP 工具是经既有边界接入的新工具来源,不是新权限形态(权限操作需要新增 Kind 枚举值,属扩展点接入,不改判定顺序与优先级)。
- 不在沙箱内运行 MCP 服务器进程(host 侧直启,对齐源端;沙箱化留待沙箱路线图另议)。

## 验收标准

- **AC1(F1)**:用户级与项目级配置中的服务器均被发现与解析;同名条目项目覆盖用户且位置保留;`command`/`url` 缺失或并存、缺 name 等非法条目整条跳过且来源/原因在加载报告可见;`/mcp` 列表与实际加载一致。
- **AC2(F2)**:配置多个服务器时启动后自动全部连接(eager);stdio 服务器对探测不响应时 10 秒后回退旧握手并连接成功;某服务器连接失败时其余服务器正常可用,失败原因可见;关闭服务后子进程全部退出、无残留。
- **AC3(F3)**:小 schema 工具直接出现在模型工具清单且可直调;大 schema 工具不在清单中,经发现工具查到 schema 后经 `mcp_call` 调用成功;强制环境变量可将 eager 改为 dispatch(反向同理);含特殊字符的 server/tool 名归一化后命名唯一且可调用;同名工具后注册覆盖可观察。
- **AC4(F4)**:MCP 工具调用先过 pre_tool_use hook(可被 reject 拦截),再过权限门:默认 ask、批准后执行、拒绝后模型收到拒绝结果;参数按目标 schema 强转(字符串数字、布尔等);文本结果回模型,空结果给占位文本;`mcp_call` 调用未知工具时收到含全部可用工具的指引错误。
- **AC5(F5)**:连接失败、调用失败、未知工具三种错误分别以各自的形态可观察(报告/状态栏、错误标记结果、指引错误),互不混淆。
- **AC6(F6)**:有 instructions 的服务器在首轮 run 以系统提醒注入模型可见文本,后续轮次不重复;无 instructions 的服务器无注入。
- **AC7(F7)**:修改任一级配置文件后无需重启,下一次 `/mcp` 或事件触发即生效;新增/删除/变更服务器可感知;`/mcp reload` 报告重载前后数量变化;重载引发的断开/重连落会话事件,重启后投影一致;主配置其余键修改不引发任何运行时行为变化。
- **AC8(F8)**:配置 http 动作的 hook 触发后,测试用本地 HTTP 服务器收到与配置一致的请求(方法、头、体,头值经环境变量展开);响应体按截断上限回流下一轮 run;请求超时与一般失败可区分且 `on_error` 各取值行为正确。
- **AC9(N1/N5/F9)**:超限(文件大小/条目数/工具数/输出长度)与异常(不可读文件、符号链接、进程秒退)被跳过或截断且有报告;TUI 与会话服务不崩溃、输入不被阻塞;工具调用与服务器状态事件落盘,服务重启后会话投影一致。
