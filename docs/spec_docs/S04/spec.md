# S04 Linux 沙箱、网络与 KiCad 工作流 Spec

> 状态：已完成（2026-10-07 系列收尾确认）。S04 对应平台可移植性路线图阶段 4；本轮交付 Linux x86_64，macOS/Windows 保持未实现或明确不可用。

## 背景

S01–S03 已将平台边界、沙箱接口和候选安全事务抽出。Linux 目前已有 bubblewrap、网络代理、无头 ERC 和 Xvfb/KiCad 会话实现，但仍有阶段 4 的闭环缺口：已批准的网络授权尚未从执行权限传入一次性沙箱；KiCad 的无头检查、GUI 会话和 doctor 使用的工具、配置、显示假设不完全统一；会话超时、取消、截图失败和进程清理需要统一 fail-closed 诊断。非 Linux 本轮不开放受保护执行能力。

## 目标

- 以现有 Linux namespace/bubblewrap 约束作为隔离基线，确保一次性命令、无头 ERC 和 GUI 会话都经过同一安全边界。
- 将已批准且已固定解析地址的网络授权传入一次性沙箱；所有未授权、解析变化、代理不可用和能力不足情况拒绝执行。持久隔离会话继续拒绝网络授权。
- 统一 KiCad 无头 ERC、GUI 会话、截图和生命周期使用的工具发现、私有配置、显示能力和候选工程边界。
- 让超时、取消、子进程残留、候选/正式工程写入越界和诊断失败都产生可区分的失败状态，并且不以主机直跑或无保护写入降级。
- 通过 Linux 定向测试、沙箱/网络/GUI 端到端场景和文档证据完成 S04 验收；不宣称 macOS/Windows 已支持。

## 功能需求

- **F1 Linux 隔离执行**：每次受保护执行都必须使用独立的 PID/网络隔离环境；正式工程以只读方式提供，候选工程和私有运行目录按明确边界提供写入；环境变量、挂载点、工作目录和命令参数经过校验。隔离探测失败、根目录不安全或代理助手缺失时拒绝执行，不得主机直跑。
- **F2 一次性网络授权**：一次性命令获得执行许可后，只有权限范围中明确批准的协议、主机和端口可以经可信代理访问；授权必须携带固定解析地址，并在每次连接前重新校验解析结果。未授权目标、解析变化、重复/歧义授权和代理不可用时连接失败。持久隔离会话带网络授权时明确拒绝创建。
- **F3 无头 KiCad 检查**：ERC 检查只能在隔离环境中调用可验证的 kicad-cli；工具版本、KiCad 配置、库依赖和模板来源必须可诊断且位于允许范围。检查前后校验正式/候选工程摘要，报告只能从私有运行目录安全读取并受大小限制；工具不可用、报告无效或工程发生变化时，验收结果为阻断而非通过。
- **F4 KiCad GUI 会话**：GUI 会话只能打开允许范围内的候选工程，使用私有无头显示和私有 KiCad 配置；启动、重启、观察、截图、超时、取消和恢复都返回可识别状态。窗口身份、工程摘要、显示进程和 KiCad 进程必须绑定到当前会话与候选；停止时只清理本会话创建的进程和锁文件，不能影响无关进程。
- **F5 工具与能力诊断**：doctor 和运行时检查使用与实际隔离环境一致的工具发现和配置规则，分别报告 Python、KiCad CLI/GUI、显示、截图和沙箱能力；主机可见但隔离环境不可用的工具不能报告为可用，缺失项要给出具体原因和受影响能力。
- **F6 Fail-closed 与可诊断拒绝**：路径越界、正式工程写入、网络未授权、隔离能力缺失、超时/取消、进程清理失败、截图或报告不安全等情况必须拒绝或阻断，并返回可区分的原因、对象和后续处理状态；任何失败不得产生“已完成”或“已验收”的假状态。
- **F7 Linux 回归与边界保持**：既有候选生命周期、摘要校验、敏感环境过滤、文件大小/数量限制和会话代际校验继续生效；S04 的新增行为不得绕过 S03 的正式/候选工程边界。

## 非功能需求

- **N1 安全不变量**：任何受保护执行都不能写入正式工程、越过允许根目录、读取未授权主机文件或通过未授权网络目标；隔离和代理边界失效时必须拒绝。
- **N2 Linux 范围**：S04 只声明 Linux x86_64 开发环境的实现与验证；macOS/Windows 保持未实现或明确不可用，不以目标编译替代真实支持声明。
- **N3 可重复验证**：沙箱 profile、网络授权、摘要校验、GUI 会话代际和错误分类应有不依赖真实模型服务的确定性契约测试；依赖本机 KiCad、Xvfb 或 bubblewrap 的场景需明确环境前置条件。
- **N4 兼容性**：保持现有命令、候选状态、能力请求协议、报告格式和已批准权限语义兼容；新增拒绝状态必须可由现有调用方安全处理。
- **N5 资源控制**：沿用并明确命令超时、输出上限、ERC 报告上限、截图/日志上限和会话清理时限；取消后不得遗留由本次运行创建的进程或临时目录。
- **N6 可诊断性**：拒绝、阻断、超时、取消、恢复和清理失败必须携带稳定的类别和对象信息，doctor、日志或 capability 结果可以区分这些状态。
- **N7 文档与证据**：S04 的四份规格文档、实现任务、验收清单和 S00 能力矩阵更新必须记录实际验证范围，明确哪些 Linux GUI/KiCad 场景因环境限制未执行。

## 不做的事

- 不实现 macOS 或 Windows 的沙箱、网络代理、GUI、KiCad 工具链或真实主机验收。
- 不为持久隔离会话开放网络授权；本轮只接入一次性执行。
- 不扩展到 KiCad DRC、PCB 编辑、自动修复策略或新的判据决策。
- 不改变候选 acceptance/rewind 事务、正式工程恢复语义或 S02/S03 已批准的安全文件契约。
- 不重做权限审批 UI、模型 provider 网络访问或通用网络策略；只接入已有权限范围到一次性沙箱。
- 不交付发行包、安装器、跨平台 CI、SQLite 驱动替换或产品支持声明更新到非 Linux。
- 不把 doctor 的“发现工具”扩展成自动安装或自动修复流程。

## 验收标准

- **AC1（F1）**：在 Linux 隔离探测中验证正式工程只读、候选/运行目录可按授权写入、宿主哨兵不可见、PID 与网络隔离生效；缺少 bubblewrap 或 profile 不安全时执行被拒绝且无宿主残留。
- **AC2（F2）**：一次性执行携带已批准网络授权时，固定目标可经代理连接；未授权目标、端口/协议不匹配、DNS 解析变化、重复授权和代理缺失均被拒绝；持久会话携带授权时创建失败。
- **AC3（F3）**：对有效、缺失、不可用或异常版本的 kicad-cli 执行 ERC；有效报告能完成计数，工程摘要变化、报告越界/超限/格式错误或工具不可用时结果为阻断，正式工程保持不变。
- **AC4（F4）**：对候选工程执行 GUI 启动、观察、截图、重启、取消和恢复；成功结果包含当前会话代际、窗口身份、工程摘要和受限证据路径；显示或 KiCad 进程异常时返回 stale/blocked 等明确状态并清理本次会话进程。
- **AC5（F4/N1）**：停止或恢复 GUI 会话后，仅本会话创建的 Xvfb、KiCad 进程和自有锁被处理；注入无关 PID、无关锁或正式工程路径不会导致误杀或正式工程变化。
- **AC6（F5）**：在主机工具存在但隔离环境不可见、显示工具缺失、模板缺失或沙箱不可用的组合下运行 doctor；输出逐项标记真实能力和具体原因，不把主机 PATH 的假阳性报告为可用。
- **AC7（F6）**：对路径越界、正式写入、未授权网络、超时、取消、代理故障、报告故障和清理失败分别触发调用；每种结果都能区分类别与对象，且不会生成成功或已验收状态。
- **AC8（F7/N4）**：既有候选生命周期、摘要/依赖失效、敏感环境过滤、文件限制和会话代际测试全部通过，新增网络和 KiCad 链路不绕过 S03 安全边界。
- **AC9（N2/N3）**：Linux 目标构建、平台无关契约测试、Linux 沙箱测试和 Python worker 测试通过；需要真实 KiCad/Xvfb/bubblewrap 的测试记录环境前置条件和实际结果。
- **AC10（N5）**：命令、ERC、截图和 GUI 会话在超时/取消后于规定时限内停止；检查进程树和运行目录确认没有由本次执行遗留的子进程或临时文件。
- **AC11（N6）**：日志、capability 响应或 doctor 输出能区分拒绝、阻断、超时、取消、恢复和清理失败，并包含可处理对象。
- **AC12（N7）**：spec.md、plan.md、task.md、checklist.md 和 S00 矩阵更新已落盘；文档明确 Linux 已验证项与未执行的环境依赖项，不声明非 Linux 支持。
