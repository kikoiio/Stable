# V02 工程依赖变化后的证据失效 Spec

## 背景

V01 已能在验收标准或原理图变化后撤销旧结论，但工程检查还依赖项目 ERC 设置、符号库配置与内容、检查时使用的全局符号库配置，以及检查器版本。当前达标状态未核对这些依赖；原理图不变时，旧证据仍可能被当作当前证据。

本轮对应路线图 V02，沿用现有单机 Linux、固定传感器板、ERC 和指定连线检查能力。依赖追踪先按检查类别划分，允许无关符号库配置变化保守地触发一次 ERC 复核。

## 目标

- 工程依赖或检查器版本变化后，受影响的达标结论在下一次状态查询、导出或目标运行周期退回待复核，并说明变化来源。
- 只重查受影响的检查类别；未受影响的证据继续有效。
- 对已结束的目标自动重新检查；依赖缺失、损坏或无法确认时明确提示，不沿用旧达标结论。
- 状态与导出能显示证据所依据的设计、验收条件、工程依赖和检查器版本。

## 功能需求

- **F1 依赖范围**：对每类检查记录其实际依据的工程输入与检查器版本。首轮覆盖项目 ERC 设置、项目符号库表及库文件、检查时使用的 KiCad 全局符号库表与路径变量；连线检查记录自身版本。
- **F2 变化发现**：用户或工具直接修改上述输入后，下一次状态查询、导出或目标运行周期发现变化。首次查询或导出在返回前持久化受影响结论为“待复核”，记录原因，并唤醒已结束的目标。
- **F3 定向失效**：项目设置或符号库依赖变化只使 ERC 类证据失效；连线证据保留。某检查器版本变化只使该检查器产出的证据失效。旧证据保留为历史。
- **F4 自动复核**：系统仅对失效的检查类别重新运行独立检查，并结合仍有效的证据判断目标是否达标。检查期间依赖再次变化时，旧依赖下产生的结果不能确认最新目标达标。
- **F5 不可用依赖**：依赖缺失、损坏或版本无法确认时，受影响结论保持待复核，状态说明原因；不能借用旧结果宣布达标。
- **F6 可追溯状态与导出**：用户能看到每项当前或历史证据对应的设计版本、验收条件版本、工程依赖版本、检查器版本、覆盖范围与失效原因，也能看到仍缺哪些当前证据。

## 非功能需求

- **N1 一致性**：依赖版本、证据失效、目标待复核状态与唤醒记录须一致地持久化；查询不能返回“新依赖已被发现、旧结论仍达标”的组合。
- **N2 可恢复与幂等**：进程中断、重复查询或重复唤醒后，目标仍能继续复核；同一次变化不反复制造失效事件或冲突状态。
- **N3 旧数据诚实迁移**：旧证据没有工程依赖版本时显示“未知”，不推断成当前版本；升级后自动复核需要当前证据的目标。
- **N4 可靠识别**：以输入内容和实际检查器版本识别变化，不能只依赖修改时间；输入不可读取时按无法验证处理。
- **N5 独立、可复现验收**：达标仍由工具检查证明；在当前单机 Linux、固定传感器板范围内，用本地可复现的变更和测试验证，不依赖真实模型服务。

## 不做的事

- 不覆盖 PCB、DRC、仿真等其他检查类别。
- 不自动把外部库符号同步进原理图；外部符号库变化只触发适用检查的证据复核。
- 不追踪到单个符号或任意宿主配置文件；依赖范围限于检查时选用的输入，并按检查类别保守失效。
- 不新增修复工具、验收标准种类或实时文件监听。

## 验收标准

- **AC1（F1–F3）**：目标已达标后，保持原理图和验收标准不变，修改项目 ERC 设置；首次状态查询返回待复核及变化原因。ERC 证据变为历史，连线证据仍为当前证据。
- **AC2（F1–F3）**：分别修改项目符号库表或库文件、检查所用的全局符号库表或路径变量、KiCad 检查器版本；每次仅使对应的 ERC 类证据失效。连线检查器版本变化时仅使连线类证据失效。
- **AC3（F2、F4）**：对工作流已结束的目标，在发现变化的查询返回前，新状态和唤醒已持久化；无需用户再次下令便自动复核。无关检查不重跑，保留的证据 ID 不变。
- **AC4（F4）**：在检查期间再次修改依赖；旧依赖下的检查即使通过，也不能确认最新目标达标，随后按新依赖复核。
- **AC5（F5）**：删除或损坏受监测依赖，或使检查器版本无法确认；状态和导出显示待复核及原因，自动检查不可用时仍不显示达标。
- **AC6（F6）**：状态与导出分别标明当前和历史证据的设计、条件、工程依赖及检查器版本、覆盖范围和失效原因；旧报告不作为当前交付报告。
- **AC7（N2、N4）**：仅改文件修改时间而内容不变，不触发失效；内容已变但修改时间相同，仍能发现。重复查询、重启和重复唤醒不产生冲突结论。
- **AC8（N3、N5）**：升级旧数据后，缺少依赖版本的证据显示“未知”，不能充作当前达标依据；在固定传感器板和本地检查器环境中无需真实模型服务即可复现上述流程。
