# V02 工程依赖变化后的证据失效 Checklist

> 依据：已批准的 [spec.md](spec.md)、[plan.md](plan.md) 和 [task.md](task.md)。开发完成后逐项运行或观察，并在通过时勾选；每项记录实际命令、结果和必要的证据位置。验收环境为本地 Linux、固定传感器板及独立 KiCad/连线检查器，不依赖真实模型服务。

## 依赖识别与定向失效

- [x] **AC1 项目 ERC 设置**：从已达标目标出发，保持原理图和验收标准不变，修改影响 ERC 的项目设置；首次状态查询返回“待复核”与变化原因，旧 ERC 证据归入历史，连线证据仍为当前且 ID 不变。（验证：运行 V02 项目设置端到端场景，比较变更前后状态、证据 ID 和历史记录）
- [x] **AC2 项目符号库表**：只修改项目符号库表内容，查询后仅 ERC 类证据失效，连线类证据保持当前。（验证：运行 V02 项目库表场景，比较两类证据的当前性和 ID）
- [x] **AC2 项目符号库文件**：只修改当前设计所用项目符号库文件内容，查询后仅 ERC 类证据失效，连线类证据保持当前。（验证：运行 V02 项目库文件场景，比较两类证据的当前性和 ID）
- [x] **AC2 全局符号库表**：在检查所用的 KiCad 配置环境中只修改全局符号库表，查询后仅 ERC 类证据失效。（验证：运行 V02 全局库表场景，检查状态中的变化来源与两类证据）
- [x] **AC2 路径变量**：改变检查所用、参与符号库解析的路径变量；查询后 ERC 类证据失效，连线类证据保持当前，状态与导出不泄露路径变量原值。（验证：运行 V02 路径变量场景，比较证据并查看状态与导出）
- [x] **AC2 检查器版本**：分别改变 KiCad CLI 和 Stable 连线检查器的可确认版本；前者仅使 ERC 类证据失效，后者仅使连线类证据失效。（验证：运行 V02 两个版本变化场景，记录两类证据 ID、当前性和复核次数）
- [x] **F1 来源边界**：仅改变未被当前检查选用的宿主配置或其他工程文件，不产生依赖失效；检查选用的项目和全局来源均可在状态中辨认。（验证：固定目标，分别改动选用和未选用来源，比较状态、依赖摘要及失效事件）

## 查询、复核与并发

- [x] **AC3 查询先持久化**：对工作流已结束的达标目标，首次状态查询在返回前已将受影响结论和原因持久化为待复核，并记录可补送的唤醒；重新打开存储仍读到同一状态。（验证：V02 端到端场景中首次查询后立即读取持久状态和事件，再重启读取）
- [x] **AC3 导出先刷新**：不先查询而直接导出发生依赖变化的目标，导出前同样完成待复核持久化和唤醒，旧通过报告不作为当前交付。（验证：独立基线目标只调用导出入口，检查持久状态、事件和导出）
- [x] **AC3 自动定向复核**：依赖恢复可用后无需再次下令，已结束目标自动复核缺失类别；无关检查器未重跑，保留的证据 ID 不变，最终结论综合两类当前证据。（验证：运行项目依赖及连线版本端到端场景，统计检查调用并比较证据 ID）
- [x] **AC4 检查中再次变化**：检查运行期间改变所依赖的输入，即使旧输入下检查通过也不能让最新目标达标；随后以新依赖再次复核并产生匹配的新证据。（验证：在可控检查器返回前改动输入，观察旧结果、目标状态和后续复核）
- [x] **N1 原子状态**：依赖变化被发现后，任何一次查询、导出或目标运行都不会显示“新依赖已记录且旧结论仍达标”；受影响证据、目标状态、原因和唤醒事件一致。（验证：在事务提交边界及重启场景查询存储，核对状态与事件）
- [x] **N2 唤醒可恢复**：首次投递唤醒失败或进程中断后，查询仍返回持久待复核；补送或重启后能继续复核，不需用户重新提交目标。（验证：让唤醒端暂时不可用，查询、重启、恢复后观察事件消费与结论）
- [x] **N2 多目标隔离**：同一次状态列表或对话状态查询中，只有依赖变化影响的目标退回待复核，其他目标的证据和状态保持不变。（验证：准备两个依赖不同的目标，改变其中一个目标的输入后查询列表和对话状态）

## 不可用、追溯与迁移

- [x] **AC5 缺失或损坏**：删除必需依赖或提供损坏的配置/库文件时，状态与导出显示待复核和可读原因；自动检查无法完成时也不显示达标；恢复输入后可重新取得当前证据。（验证：分别运行缺失、损坏、恢复场景，核对状态和导出）
- [x] **AC5 版本未知**：使 KiCad 或连线检查器版本无法确认时，对应类别保持待复核并说明原因，旧证据不能使目标达标；版本重新可确认后复核。（验证：运行两个版本不可用及恢复场景）
- [x] **AC6 当前证据出处**：状态与导出对每项当前证据显示设计版本、验收条件版本、工程依赖版本、检查器版本及覆盖范围；字段与实际检查时输入一致。（验证：达标后对照检查记录、状态和导出）
- [x] **AC6 历史与缺口**：发生定向失效时，状态与导出清楚区分当前/历史证据，历史项显示失效原因及原出处，并列出尚缺的当前证据；旧报告不标为当前交付。（验证：在自动复核完成前导出，核对历史、缺口和报告归属）
- [x] **AC7 内容判定**：只改受监测文件的修改时间而不改内容，不产生失效；改变内容后恢复原修改时间，仍能发现变化。（验证：在同一达标目标上依次运行两种文件操作，比较依赖摘要、状态和事件数）
- [x] **AC7 幂等**：同一依赖变化后重复查询、重复唤醒及重启，不重复制造失效事件或相互矛盾的结论；再次真实内容变化才产生新失效。（验证：记录事件数、代次和状态，多次查询及重启后比较）
- [x] **AC8 旧数据迁移**：升级 V01 数据后，无依赖版本的旧证据显示“未知”且保留为历史；原已达标但缺当前证据的目标变为待复核并可自动重查，不能沿用旧达标。（验证：使用 V01 数据副本升级，比较升级前后证据、状态和唤醒事件）

## 集成与回归

- [x] **统一入口**：命令行状态/导出、对话状态与目标运行周期均能在返回或决策前发现同一类依赖变化，结果一致。（验证：对独立目标分别从各入口触发相同变化，比较状态、原因及证据）
- [x] **旧动作守卫**：依赖变化后，变化前的检查结果、决策或待执行动作不能更新最新目标为达标，也不能执行旧动作。（验证：使用可控延迟检查/动作场景，比较变化前后目标与动作记录）
- [x] **构建与静态检查**：项目编译通过，Go 源码格式正确，差异无空白错误；仓库若配置 lint 命令则通过。（验证：运行 `GOPROXY=off GOSUMDB=off go build ./...`、`gofmt -l` 对本次变更的 Go 文件检查、`git diff --check`，以及已配置的 lint 命令）
- [x] **自动化回归**：Go 单元测试、KiCad Python 测试、V01 标准变化端到端及 V02 依赖变化端到端均通过。（验证：运行 `GOPROXY=off GOSUMDB=off go test ./...`、`python3 -m unittest discover -s workers/kicad -p 'test_*.py'`、`bash tests/e2e/criteria_change.sh`、`bash tests/e2e/dependency_change.sh`，四项退出码均为 0）
- [x] **完整用户场景**：固定传感器板目标达标 → 用户直接改项目 ERC 设置 → 首次查询看到待复核与原因 → 系统自动仅重查 ERC → 用户再次查询看到结合原连线证据的新结论 → 导出包含当前和历史出处；全过程无需真实模型服务。（验证：运行 V02 完整端到端场景，保存两次状态、检查调用、证据 ID 和最终导出）
