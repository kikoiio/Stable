# J00 云端兼容性与候选隔离试验 Spec

## 背景

Stable 目前围绕固定 KiCad 夹具运行；`docs/PLAN.md` 要求先确认嘉立创EDA专业版在 Linux 云端环境中的可启动性、接口覆盖、工程格式支持和候选身份隔离。若没有这些证据，后续写入能力可能误操作正式工程或关联云端对象。

## 目标

- 在干净、可重复的 Ubuntu x64 GitHub Actions 环境中，固定一个候选客户端版本和公开最小 `.eprj3` 夹具。
- 形成可重复执行的探针，观察客户端发现、启动、CLI/MCP、工程读取、参数修改、保存、重开、规则检查和 BOM/网表/截图导出。
- 验证独立 profile、全离线运行、工程身份、自动保存/恢复与桥接边界，证明候选不会修改正式工程或关联云端对象。
- 输出带版本、摘要、运行参数、真实退出状态和清理结果的兼容性报告与能力表。
- 若写入或隔离无法证明，明确把对应能力收窄为只读/建议，并阻止后续阶段假设其可用。

## 功能需求

- **F1 基准与环境固定**：使用公开的最小 `.eprj3` 工程、明确的客户端版本、Ubuntu x64 环境和可记录的安装包摘要；每次试验记录输入与环境身份。
- **F2 客户端与接口发现**：判断客户端是否安装、可启动、版本是否满足要求，以及 CLI、MCP/桥接、隐藏窗口和所需扩展接口分别是否可用；缺失能力区分“未安装”“不支持”“需激活”与“试验失败”。
- **F3 工程识别与读取**：在授权目录内打开夹具，确认工程格式、入口、文件集和工程身份，并读取器件、参数、引脚、网络及文档范围；路径越界、格式不支持或依赖缺失必须明确失败。
- **F4 受控修改探针**：对预先定义且可独立核验的参数执行一次小范围修改，记录修改前条件、目标对象、实际结果和返回状态；对象不匹配或前置条件变化时不得继续写入。
- **F5 保存与重开**：修改后保存，等待状态稳定，再通过新的有效会话重开并读取实际结果；区分“保存成功”“文件可重开”“参数确实持久化”。
- **F6 检查与导出探针**：分别探测原理图规则、网络/结构读取、BOM、网表、截图和报告导出；每项结果单独记录为通过、失败或不可用，不得用一项结果替代另一项。
- **F7 候选隔离**：在独立运行目录、profile 和候选副本中执行试验，验证候选路径、工程身份、自动保存、恢复和桥接均未改变正式工程或关联云端对象；全离线能力单独记录。
- **F8 会话监督与清理**：客户端、桥接、显示服务和子进程由同一试验生命周期管理；超时、崩溃、取消或重启后能重新观察实际状态，结束时确认本次启动的进程和临时资源已退出。
- **F9 可重复云端执行**：试验可在干净 runner 上重复运行，保存脱敏日志、必要报告和摘要；同一输入在允许的环境差异内得到一致的能力结论。
- **F10 能力边界与退出闸门**：报告将能力标为“已验证”“受限支持”“不可用”或“未验证”，并列出证据、限制和下一步；未通过候选隔离的能力不得进入后续写入阶段。

## 非功能需求

- **N1 可重复性**：客户端版本、安装包摘要、系统镜像、夹具摘要、启动参数、环境变量允许列表和探针版本均可追溯；同一版本的重复运行不依赖上一次运行残留。
- **N2 安全边界**：公开云端试验只使用公开代码、夹具和脱敏日志；不得上传真实工程、账号 profile、激活数据、provider 密钥或其他非公开凭据。正式工程路径在试验环境中不可写。
- **N3 失败关闭**：不能确认候选身份、接口返回、保存状态、检查覆盖或清理状态时，结论必须是失败/不可用/未验证，不得推断为通过，也不得自动重放状态不明的写操作。
- **N4 证据完整性**：每项能力结论绑定客户端/探针/检查器版本、工程摘要、报告摘要、真实退出状态、产物摘要和覆盖范围；日志与产物来源可追溯。
- **N5 资源约束**：单个云端 job 使用一个客户端实例，设置明确的总时限、操作时限、磁盘和内存观测；缓存、临时文件和产物有界，失败时保留必要证据。
- **N6 进程与文件清理**：试验结束或中断后，客户端、桥接、显示服务、子进程和运行目录状态可验证；不得终止其他任务的进程或删除仍被占用的资源。
- **N7 兼容性分层**：把客户端发现、读取、写入、重开、检查、导出、隔离和恢复分别报告；某一层通过不能替代其他层。
- **N8 人工与云端授权边界**：文档和本地轻量准备可以先完成；首次调用 GitHub Actions、下载客户端或上传夹具前，必须明确服务、用途、权限、数据范围和潜在费用并取得用户授权。

## 不做的事

- 不实现嘉立创正式应用适配器、Stable 生产工具注册、现有 Goal/Run/Candidate 的接入或用户可见写入能力。
- 不处理真实用户工程、商业账号、登录/激活凭据、云端工程同步或任何非公开设计数据。
- 不把本机一次性成功当作云端支持；不在未经授权的情况下触发 GitHub Actions、下载受许可约束的软件或上传数据。
- 不宣称支持 PCB 编辑、复杂仿真、任意 JavaScript、任意脚本执行、自动采购、自动上传或跨软件适配。
- 不要求 J00 完成全部规则语义、性能验证或模型端到端任务；只能记录这些能力是否可探测及其边界。
- 不因客户端命令返回 `ok`、截图生成或单个检查通过，就宣布工程修改、网络正确、电气性能或候选隔离成立。
- 不在隔离未证明时开放后续阶段的参数修改、连接修复、器件替换或正式接收。

## 验收标准

- **AC01（F1）**：在干净 Ubuntu x64 runner 中，使用固定客户端版本、安装包摘要和公开最小 `.eprj3` 夹具完成环境记录；重复运行不会依赖上次残留。
- **AC02（F2）**：探针输出客户端版本、启动结果、CLI、MCP/桥接、隐藏窗口及扩展能力；每项均明确标记已验证、受限支持、不可用或未验证，并能区分未安装、需激活与试验失败。
- **AC03（F3）**：授权目录内的夹具被识别为预期格式和工程身份，器件、参数、引脚、网络与文档范围和独立预期一致；越界、损坏或缺失依赖被拒绝。
- **AC04（F4）**：预定义参数修改只作用于批准对象；对象、旧值或前置条件不符时无写入副作用，并保留操作前后证据。
- **AC05（F5）**：保存后的候选可由新有效会话重开，读取结果确认参数已持久化；保存返回成功但重开或读取失败时结论不通过。
- **AC06（F6）**：规则、网络/结构、BOM、网表、截图和报告分别得到通过、失败或不可用结果；导出文件存在、非空、格式正确且绑定当前工程摘要。
- **AC07（F7）**：候选、独立 profile、自动保存/恢复和桥接身份均与正式工程分离；全离线试验期间正式工程及关联云端对象无变化，并有可审阅证据。
- **AC08（F8）**：超时、崩溃、取消和重启后探针能重新观察真实状态，未知写结果不会盲目重放；结束后本次启动的客户端、桥接、显示服务和子进程均已退出。
- **AC09（F9）**：同一 workflow 在干净 runner 上可重复执行，生成脱敏日志、能力表、兼容性报告和必要产物；报告包含提交 SHA、环境、版本、摘要、退出状态和清理结果。
- **AC10（F10）**：报告明确 J00 退出结论：至少一条“读取→受控修改→保存→重开→检查→导出”闭环通过，且候选隔离和进程清理通过；否则明确阻塞原因和收窄后的能力边界，后续阶段不得假设写入可用。
