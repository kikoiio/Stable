# V01 验收条件变化后的结论失效 Spec

## 背景

Stable 当前支持固定传感器板目标、验收标准版本、ERC 与指定连线检查，以及目标状态和结果导出。用户可以确认现有目标的新验收标准，但现有流程未可靠地使旧证据和已完成结论失效。因此，新标准生效后，状态或导出仍可能把旧结果当作当前目标达标的依据；检查进行中修改标准也可能产生同样的问题。

本轮对应路线图 V01，沿用现有传感器板目标与检查、修复能力，先证明验收条件变化能使当前结论可信地退回待复核。

## 目标

- 新标准确认后立即显示当前目标待复核，并保留可追溯的旧证据。
- 系统自动按新版标准完整复核；未达标时沿用现有能力尝试修复。
- 即使验证过程中再次更改标准，旧版结果也不能确认新版目标达标。

## 功能需求

- **F1 标准版本**：用户确认现有目标的新验收标准时，系统先校验标准，再产生可追溯的新版本。无效或不支持的标准不改变目标。
- **F2 立即失效**：新版本生效时，当前结论立即显示“待复核”，并说明原因和当前标准版本。上一版本的证据保留为历史记录，但不能继续证明当前目标达标。确认成功的响应不得早于这一状态生效。
- **F3 证据出处**：新产生的验收证据应说明所证明的主张、覆盖范围、产物版本、标准版本、检查器及版本、来源等级和失效依据。历史证据缺少的信息应明确标为未知，不得补写成已知事实。
- **F4 自动复核**：系统自动按新版标准完整复核，包括此前已验证完成的目标。若新标准未满足，系统可以沿用现有修复能力继续尝试；现有能力无法处理时，应显示未满足项及需要用户处理的原因。
- **F5 验证中改标准**：验证进行中若新标准生效，针对旧版标准的检查或修复结果不能使最新版目标变为达标。系统应转而按最新标准复核。
- **F6 状态与导出**：状态和导出只将适用于当前标准与当前产物的证据作为达标依据。历史证据仍可查看，并能辨认其所属版本及失效原因；旧检查报告不能作为新版当前报告交付。

## 非功能需求

- **N1 一致与持久**：新标准和“待复核”结论须作为一致的持久状态对外可见。进程中断或重复事件不能留下“新版标准、旧版达标结论”的组合。
- **N2 既有数据可追溯**：升级后，既有目标和证据仍可读取、导出和追溯；缺少新版所需出处信息的旧证据不得被当作已具备该信息。
- **N3 版本化契约**：事实存储格式和证据格式应有带版本号的简短数据契约，说明既有数据如何迁移或解释。
- **N4 独立验证**：达标结论仍以独立检查的结果为依据；模型判断、对话和截图不能替代检查证据。
- **N5 可复现范围**：本轮在当前单机 Linux、传感器板夹具和已有验收标准种类内完成；核心行为应可用可复现测试验证，不依赖真实模型服务。

## 不做的事

- 不新增验收标准种类、板型或修复工具；新版标准超出现有修复能力时，明确说明并交给用户。
- 不处理项目设置或检查规则变化引发的证据失效；该能力属于 V02。
- 不做逐项证据复用或多工作项重排；本轮在标准变化时使当前结论整轮失效并完整复核。细粒度重排属于后续小愿景。
- 不建设新的执行器、沙箱或桌面动作能力；这些能力属于 V04–V09。

## 验收标准

- **AC1（F1）**：给现有目标确认合法新标准后，观察到标准版本增加；提交无效或不支持的标准后，版本、状态与证据均不变。
- **AC2（F2、F6）**：已达标目标确认新标准后，暂缓新版复核并在确认返回时查询状态和导出；两者均显示新版“待复核”、原因及版本，且当前达标标记为否；旧证据仍可查看。
- **AC3（F3）**：查看新产生的每条验收证据，可识别主张和覆盖范围、产物与标准版本、检查器及版本、来源等级、失效依据；旧数据缺失的信息明确显示为未知。
- **AC4（F4）**：原本已完成的目标更改标准后，无需再次下达命令，系统自行复核。现有修复能力可处理时继续尝试，并以新版证据确认结果；处理不了时列出未满足项和原因。
- **AC5（F5）**：人为放慢一次检查，在检查期间再次确认新标准；旧版检查即使返回通过，也不能使最新版目标变为达标，后续按最新版重新复核。
- **AC6（F6）**：导出只把当前标准与当前产物对应的证据作为达标依据；历史证据保留并标明所属版本及失效原因，旧 ERC 报告不会作为新版当前报告交付。
- **AC7（N1–N3）**：在标准确认或自动复核前后中断并重启，仍不会出现新版标准配旧版达标结论；已有数据可读取，重复唤醒不会制造相互矛盾的当前状态。
