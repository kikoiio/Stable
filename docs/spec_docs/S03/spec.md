# S03 安全文件访问与候选验收事务 Spec

> 状态：已批准（2026-10-06）。S03 对应平台可移植性路线图阶段 3。范围采用三平台契约：Linux 保持现有行为，macOS/Windows 做编译与可在 Linux 运行的契约测试，真实 OS 验收留阶段 5。

## 背景

S02 已完成平台路径、IPC、锁、进程生命周期和私密文件边界的抽取，但候选工程的安全文件访问与验收事务仍依赖 Linux 专属原语。候选 manifest、ERC 报告和工作区文件读取需要统一的根目录约束，并防止路径穿越、符号链接或 Windows reparse point 越界；候选 acceptance 与 rewind 需要在并发修改、跨卷和进程崩溃时保持可恢复，不能因平台差异退化为无保护覆盖。

## 目标

- 在 Linux、macOS、Windows 代码路径上建立一致的安全文件访问契约；Linux 保持现有行为作为回归基线。
- 统一保护候选根目录、manifest、ERC 报告及相关工作区文件的读取与写入边界。
- 保留 Linux 的原子目录交换；为其他平台提供带 journal 的分阶段提交、回滚和启动恢复，无法保证安全语义时拒绝执行。
- 覆盖 acceptance 与 rewind 在准备、交换、完成及异常终止边界的恢复行为。
- 通过三平台编译和可在 Linux 运行的契约测试验证跨平台逻辑；真实 macOS/Windows 行为验收留到阶段 5。

## 功能需求

- **F1 安全根目录解析**：所有候选工程、正式工程、manifest 和 ERC 报告路径都以明确根目录解析；拒绝绝对路径、路径穿越、越过根目录的符号链接或 Windows reparse point，并拒绝不符合预期类型的条目。
- **F2 受控文件访问**：候选读取、写入、复制、清单生成和 ERC 报告读取统一经过安全文件边界；访问过程中发现链接替换、根目录变化、文件类型变化或无法证明边界安全时，操作失败并保持已有数据不变。
- **F3 内容与版本一致性**：manifest、正式工程和候选工程的摘要、文件身份及预期版本在验收前后进行校验；文件被并发修改、删除或替换时拒绝继续，不能把未经校验的内容标记为已验收。
- **F4 Acceptance 事务**：验收更新必须记录可恢复的事务状态和正式/候选摘要。Linux 使用现有原子目录交换语义；macOS/Windows 使用分阶段提交与回滚语义。跨卷、能力不可用或无法证明安全时明确拒绝，不得退化成无保护覆盖。
- **F5 Rewind 事务**：回退快照必须遵守与验收相同的根目录、链接、并发和跨卷约束，并记录可恢复状态；任何失败都不能留下半回退的正式工程。
- **F6 崩溃恢复**：在准备、提交、交换/阶段切换和完成记录之间发生进程终止后，下一次启动能够根据事务状态恢复、回滚或明确阻断；恢复操作可重复执行且不会重复应用或丢失正式工程。
- **F7 可诊断拒绝**：安全边界、并发冲突、跨卷限制、事务恢复失败等拒绝结果包含可区分的原因，能指出需要人工处理的对象或状态；不得报告为成功。

## 非功能需求

- **N1 安全不变量**：任何平台都不得因路径解析、链接类型、跨卷限制或恢复降级而扩大可读写范围；正式工程、候选工程和事务目录之间的边界始终可验证。
- **N2 Linux 回归**：Linux 现有原子交换、验收结果、回退结果、错误语义和启动恢复行为保持不变；既有单元、集成和端到端断言无需放宽。
- **N3 跨平台验证边界**：Linux、macOS、Windows 代码路径必须通过编译；平台无关的路径、边界判定、事务状态转换和恢复逻辑必须有可在 Linux 执行的契约测试。真实 macOS/Windows 文件系统与崩溃行为列入阶段 5 验收，不在 S03 中宣称已验证。
- **N4 故障一致性**：事务和恢复操作必须幂等；在任一受支持的故障边界重启后，系统只能得到完整旧版本、完整新版本或明确阻断状态，不得暴露半写入工程。
- **N5 资源与兼容性**：沿用现有 manifest、ERC 报告和候选文件的大小及数量上限；安全校验不得取消既有敏感信息过滤、文件类型限制或候选生命周期约束。
- **N6 可诊断与可追踪**：拒绝、恢复和阻断状态可通过日志、状态查询或验收结果区分；S00 能力矩阵中与安全文件访问和候选事务对应的条目同步记录实际支持状态及证据位置。
- **N7 文档交付**：S03 的四份规格文档、实现任务和验收清单完整落盘，并明确真实 OS 验收的后续责任边界。

## 不做的事

- 不在 S03 中完成真实 macOS/Windows 主机上的启动、文件系统 ACL/reparse point、跨卷和崩溃恢复验收；这些证据留到阶段 5。
- 不修改发行包、安装器、CI 矩阵、Temporal CLI 获取方式或 SQLite 驱动选型。
- 不实现阶段 4 的沙箱、网络隔离、KiCad GUI/显示和工具链平台适配；S03 只处理候选文件访问和验收/回退事务边界。
- 不改变 S02 已确认的平台路径、IPC、锁、进程生命周期和私密文件范围，除非为接入 S03 安全边界必须修正调用契约。
- 不把安全事务降级为无 journal 的逐文件覆盖，也不以放宽路径、链接或并发校验来换取成功率。
- 不扩展候选验收之外的业务流程、UI 功能或新的验收策略。

## 验收标准

- **AC1（F1）**：对候选根目录、正式根目录、manifest 和 ERC 报告执行绝对路径、`..`、根外符号链接/reparse point、目录替代文件等测试；越界或类型不符时操作被拒绝，根外文件未被读取或修改。
- **AC2（F2）**：对候选生成、manifest 构建、ERC 报告读取、复制和写入执行安全访问测试；在链接替换、根目录替换或文件身份变化时失败，已有正式/候选数据保持不变。
- **AC3（F3）**：在验收前修改、删除或替换候选/正式文件，系统拒绝验收并报告摘要或版本冲突；未产生验收回执或“已接受”状态。
- **AC4（F4）**：Linux 验收保持现有原子交换结果；macOS/Windows 契约测试覆盖准备、阶段提交、回滚、跨卷和能力不足路径；跨卷或无法证明安全时拒绝且不发生无保护覆盖。
- **AC5（F5）**：对回退执行相同的链接、根目录、并发和跨卷场景；成功后得到完整目标快照，失败后正式工程和候选工程均保持完整可识别状态。
- **AC6（F6）**：在准备、交换/阶段切换、完成记录等故障点注入终止并重启；恢复后得到完整旧版本、完整新版本或明确阻断状态，重复恢复不会重复应用或改变结果。
- **AC7（F7）**：对路径越界、链接拒绝、并发冲突、跨卷、能力不可用和恢复阻断分别触发错误；状态查询或日志能区分原因并给出处理对象。
- **AC8（N1/N2）**：Linux 现有单元、集成、端到端验收及原子交换/恢复断言全部通过，结果与 S02 基线一致。
- **AC9（N3）**：Linux、macOS、Windows 目标编译通过；平台无关契约测试通过；文档明确真实 macOS/Windows 验收尚未在 S03 完成。
- **AC10（N4/N5）**：故障注入和边界输入不产生半写入工程；现有文件大小、数量、敏感信息过滤和生命周期限制继续生效。
- **AC11（N6/N7）**：S00 矩阵对应条目包含 S03 实际状态和证据位置；S03 规格、任务和验收文档完整落盘，且没有把阶段 5 的真实 OS 证据写成已完成。
